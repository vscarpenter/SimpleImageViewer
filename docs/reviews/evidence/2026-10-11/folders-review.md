# StillView folder browsing and performance review — October 11, 2026

Read-only review of commit `9da3f3fe853febdb47828654de7f348072c25e98`. No repository files changed. Findings below use current files, not prior scan reports. A temporary command-line probe compiled the production `FileSystemService.swift`, `ImageFile.swift`, and `UTType+ImageSupport.swift` with the installed Apple Swift 6.4 compiler (macOS 27 target). No app-wide test suite or runtime performance profile was run by this reviewer.

## Current implementation and strengths

The active viewing path is `App/ContentView.swift:99-148` → `GridPane.swift` / `FilmstripView.swift` → `StudioThumbnailLoader` in `FilmstripView.swift:117-132`. `EnhancedThumbnailGridView` and `EnhancedThumbnailGenerator` are legacy, currently absent from the rendered app path. Their separate bounded cache should not be cited as evidence that the current Studio grid has a bounded shared thumbnail cache.

Folder selection uses a persistent root-owned `FolderSelectionViewModel` (`App/ContentView.swift:8,35-36`). New scans carry a generation ID and reject stale completion (`ViewModels/FolderSelectionViewModel.swift:328-369`). The old visible folder's grant remains active while a tentative scan runs. This is a good base to preserve.

`DefaultFileSystemService` has real recursive enumeration (`Services/FileSystemService.swift:111-155`) and an active regression test exercises root + child images (`Tests/Services/FileSystemServiceTests.swift:136-160`). The app always requests `recursive: false` (`ViewModels/FolderSelectionViewModel.swift:349`). The similarly named `FolderScanner` is a stub (`Models/FolderScanner.swift:23-25`) and should not become the new implementation by accident.

Main-image decoding already preserves EXIF orientation, budgets decoded pixels before allocation, suppresses stale canceled publication, shares decode work between subscribers/preloading, and checks file revisions (`Services/ImageLoaderService.swift:162-210,246-316`; `Models/ImageCache.swift:70-115,149-158`). The cache maintains actual decoded-memory costs and responds to system memory pressure. Those improvements should be retained, not replaced with a second generic cache abstraction.

## Additional observations, intentionally below the primary findings

- Progress is synthetic: start sets 10%, completion sets 100%, and image count is only set at completion (`ViewModels/FolderSelectionViewModel.swift:335-359`). The launch screen exposes this as a real percentage to VoiceOver (`Views/FolderSelectionView.swift:244-249`). Prefer an indeterminate spinner plus actual “123 images in 18 folders” rather than inventing an unknown total.
- Full-image loading runs on every grid selection even if the inspector is hidden (`Views/GridPane.swift:23`; `ViewModels/ImageViewerViewModel.swift:840-846`). Defer full-resolution decode until Single view or another consumer actually needs it; use metadata/thumbnail for grid-only selection. Profile before choosing exact resource limits.
- Grids/filmstrips materialize an enumerated array on each render (`Views/GridPane.swift:19`; `Views/FilmstripView.swift:18`). For a 100,000-entry collection, use stable item identities and avoid repeated whole-list allocations/sorts on every incoming scan batch. No measured allocation count is claimed here.
- A child disappearing during `resourceValues` can fail the whole scan because the directory-kind read is outside the per-file catch (`Services/FileSystemService.swift:93,134`). Recursive enumeration also lacks an `errorHandler`, so inaccessible subtrees are not surfaced as partial results (`:128-130`). This must change before tree browsing ships.
- `ImageFile.id` is a fresh UUID, while equality/hash use URL (`Models/ImageFile.swift:6,120-127`). Current GridPane/Filmstrip use `.element.id`, followed by `.id(index)` for scroll targets. Probe: same URL rescanned gives `repeat_equal=true repeat_id_equal=false`. Incremental rescans would unnecessarily recreate tile state, and index scroll anchors would change under inserts/sorts. Move scroll and view identity to the stable selection ID.
- Existing `FileSystemServiceIntegrationTests.swift` has integration examples, but is not listed in the current Xcode project source list; do not report it as passing active app-hosted coverage. The active `FileSystemServiceTests.swift` does cover simple recursive scanning, hidden files, and shallow sorting. Neither covers package exclusion, cooperative cancellation, partial permission errors, or large streaming trees.
- Bookmark records are positional parallel arrays (`FolderSelectionViewModel.swift:127-145,222-258`). A moved bookmark is discarded when its resolved URL differs (`:234-239`). Persist a structured record containing bookmark + display URL + browsing scope so a rename/move is recoverable, with a migration from current arrays.

## Requested feature: all images beneath one parent folder

Interpret “sub-directions” as “subdirectories.” The goal is to choose one parent, browse a combined collection immediately, and optionally narrow to a branch without opening the picker again.

### Native UX proposal

1. Keep the current Studio grid, Single view, filmstrip, and inspector. Add a clearly labeled **Include subfolders** switch in the folder/scope control and expose the same action in View. Remember it per chosen root, not as a global surprise when opening a different folder. Selecting a parent with no direct images should still open successfully if descendants contain images.
2. When enabled, show **All images** for the selected root, an actual running image/folder count, and a small **Scanning… / Cancel** status while discovery continues. Let users view the first batch before the whole tree finishes.
3. Add an optional native source-list sidebar in a later pass: root **All images**, disclosure rows for subfolders, normal macOS selection, and per-row image counts only when known. Clicking a row narrows the existing collection rather than starting a new permission grant/picker. Reuse the right inspector. This is a source-list/detail/inspector layout, not card rows.
4. Give selected images a relative folder path in the inspector and hover/help. For duplicate basenames, show a secondary relative path in grid captions or an optional “Show filenames” mode; VoiceOver must include it. A caption-free single-folder grid cannot disambiguate several `IMG_0001.JPG` files across a tree.
5. Sort across the active scope, with a stable relative-path tie-breaker. Keep selection, scroll position, and keyboard navigation attached to file identity. Introduce filename/path search after the core scope works; do not gate this release on semantic/AI search.
6. Partial results are useful: **2 folders could not be read — Show details** and **Retry**. An empty successful tree is an empty state, a canceled partial tree retains the images already found, and an offline drive retains its previous snapshot with a clear unavailable state.

A compact rollout can deliver the combined grid and scope switch first. The optional hierarchy adds narrowing/discoverability but is not required to stop selecting each subfolder individually.

### Data and scan architecture

- Introduce a scene-owned `BrowsingSession` with root grant, scope (`folderOnly` / `folderAndDescendants`), stable selected file ID, sort, filter, folder index, scan generation, completion/partial/canceled state, and warnings. Avoid app-wide singleton selection so future multiwindow browsing can hold separate folder grants.
- Extend the real FileSystemService rather than building on the stub FolderScanner. Stream `ScanEvent` batches (`discovered images`, `folder counts`, `warning`, `complete`) through a cancellation-aware worker/actor. Keep URL/file metadata work off the main actor; publish batches on the main actor at a bounded cadence. Do not pre-enumerate an entire tree merely to produce a percentage.
- Carry stable normalized root-relative path/URL identities across scans; keep content revision separate (size + modification time, optionally resource identifier for rename detection). Preserve the original security-scoped URL for authority; do not replace its grant with a newly canonicalized URL. Use deterministic sorting with relative path as final tie-breaker and reconcile by stable identity.
- Cache only metadata during discovery. Load thumbnails for visible/near-visible tiles through one bounded shared service; coalesce equivalent requests and cancel queued demand. Limit full-resolution decodes to the selected Single-view image and small adjacent prefetch. Do not run AI over every discovered image by default.
- Use explicit scan policies: skip hidden files/directories and package descendants by default; do not descend into symbolic-link directories or mounted volumes by default; omit symlink file targets escaping the granted root. If alias/link following is added later, require containment and cycle detection using file-resource identity. The current access-manager containment helper already compares canonical path components and rejects sibling prefixes/link escapes (`Services/SecurityScopedAccessManager.swift:137-158`). Retain that boundary.
- Handle item-level races as warnings/skips, subtree permission errors as partial results, and root access failures as actionable failures. Preserve cancellation as its own state instead of wrapping it as “scanning failed.” Start and stop root access with the whole session lifetime, keeping a canceled worker's scope until its actual outstanding I/O finishes.
- Cloud and network stores: enumerate metadata without eagerly opening full image payloads, display a materializing/offline state only when that thumbnail/image is requested, and do not automatically download the entire hierarchy. Coordinate reads when appropriate to provider-backed URLs. Test on an actual File Provider folder and SMB mount; local `/tmp` tests cannot validate their behavior.

### Change monitoring

A root directory descriptor cannot stand in for recursive tree monitoring. Apple describes FSEvents as a hierarchy change notification API; use a root stream to mark affected subtrees dirty, then reconcile their current snapshots. Start monitoring before the initial scan, coalesce/debounce changes, and rescan when events signal dropped/coalesced changes. Treat event history as advisory. Retain a manual refresh/retry fallback for provider or network drives whose behavior differs. See [Apple File System Events](https://developer.apple.com/documentation/coreservices/file_system_events) and [Apple's snapshot and rescan guidance](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html).

Package skipping is an explicit enumeration option in [Apple's `skipsPackageDescendants` documentation](https://developer.apple.com/documentation/foundation/filemanager/directoryenumerationoptions/skipspackagedescendants). The current recursive scanner supplies only `.skipsHiddenFiles`; the production probe found `Sample.app/Contents/Resources/internal.png` in the returned collection. Exposing the current boolean without a policy change would browse inside packages.
